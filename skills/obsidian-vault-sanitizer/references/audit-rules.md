# Audit Rules And Limitations

The audit script uses conservative filesystem analysis. It is useful for a first pass, but Obsidian's live index remains authoritative for some cases.

## Link Resolution

- Wikilinks are parsed from `[[target]]`, `[[target|alias]]`, and embeds such as `![[target]]`.
- Markdown links are parsed from `[text](target)` and image links such as `![alt](target)`.
- External URLs, `mailto:`, Obsidian URI links, and pure local anchors like `#Heading` are ignored as broken-file checks.
- Links with `/` are resolved as vault-relative paths first.
- Bare note links are resolved by Markdown basename.
- Attachment links are resolved relative to the source note first, then by vault-relative path, then by unique basename.

## Heading And Block Checks

- Heading checks are best-effort and normalize case, punctuation, and whitespace.
- Block IDs are detected with `^block-id` tokens in the target note.
- Dynamic headings generated by plugins, transclusions, or templates may need manual verification.

## Orphan Attachment Checks

- The script treats non-Markdown files as attachments unless they are in ignored folders.
- A file is not reported as orphaned if a Markdown link can be resolved to it.
- Canvas files, plugin configuration, web exports, and non-Markdown references are not authoritative in the default audit. Search them manually before deletion.

## Frontmatter Checks

- If PyYAML is installed, the script validates frontmatter syntax.
- If PyYAML is not installed, the script still reports other findings and marks YAML validation as unavailable.
- Semantic property validation is vault-specific and should follow local conventions.
